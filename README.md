# sutro-mnist-submit

A self-contained, deployable copy of the **hosted submission site** for the
Sutro MNIST-medium time challenge, together with the evaluator harness it
runs. One secret link, no login: anyone holding the link pastes a
`submission.py`, picks an accuracy band and a mode, and the kernel is timed on
one A100 in the owner's [Modal](https://modal.com) account by the same
evaluator the KernelBot leaderboard uses. The page reports the ranked time,
the accuracy and what the run cost, and a ledger enforces a global spending
cap (default $50) across every submitter.

This repository exists so that another agent or person can deploy the site
from scratch without the original session. Read in this order:

## Quickstart (the whole deployment in four commands)

```bash
uvx modal setup                                  # once: log in to the Modal workspace that will pay
uvx modal deploy web/app.py                      # builds two images, deploys web + A100 worker + cron
uvx modal run web/app.py::link                   # prints the secret link to share
uv run --python 3.12 python scripts/smoke.py "<link>" --mode test   # baseline kernel end to end (~$0.06)
```

`uvx` is the [uv](https://docs.astral.sh/uv/) tool runner; it installs the
Modal CLI on the fly. If `modal` is already installed, drop the `uvx` prefix.

## What is in here

```
web/app.py            the site: FastAPI routes, ledger, A100 worker, cron, owner commands
web/runner.py         stdlib-only script the worker runs under a hard deadline
web/README.md         design notes for the site
scripts/smoke.py      submit a kernel to a deployed site and wait for the verdict
tests/test_web.py     41 unit tests for the site (no Modal account, no GPU needed)
tests/test_eval.py    the evaluator's own unit tests
eval.py, utils.py, mnist_data.py, task.py, reference.py, submission.py
                      the evaluator harness (version 1.1.0) and the kernel template
run_modal.py          the harness's standalone runner; the site reuses its Modal image and evaluate()
mnist-medium-*/       one task.yml per accuracy band (generated from bands.json by make_bands.py)
submissions/          reference kernels: ncm_baseline, pca_qda, mlp512, cg_pair
bands.json, bands.md, make_bands.py, sutro.yaml
                      the bands, the generator for every task.yml, and the competition file
results/              archived evaluator runs (CPU dry runs and A100 checks) that DESIGN.md cites
assets/               the task figure used by HARNESS.md
.github/workflows     CI: runs both test files on every push
```

The site runs the harness through `run_modal.evaluate()`, so any change to
the evaluator or to a band's timeouts is picked up by redeploying; the budget
reservations are computed from the `task.yml` timeouts at request time.

## The bands

The site offers the five accuracy bands of the challenge. A run qualifies
when, over the ranked draws, it reaches the band's required count of correct
predictions (harness 1.1.0 also applies a per-draw floor and a hold-out
check; see HARNESS.md).

## Status at snapshot time (2026-09-23)

- Deployed and verified in the `yaroslavvb` Modal workspace as app
  `sutro-mnist-submit`. Six end-to-end runs were made through the site:
  test-mode and leaderboard-mode passes, a deliberately broken kernel, and
  reruns after each redeploy. Total spend on those: about $0.30. The
  canonical copy of this repository is `cybertronai/sutro-mnist-submit`.
- A 64-agent adversarial review of the first version found 19 defects; all
  are fixed and covered by tests. They are catalogued in [LESSONS.md](LESSONS.md).
- Access is deliberately "security through obscurity": the random token in
  the URL is the only gate. GitHub login is a planned follow-up; the hook for
  it is the `check()` function in `web/app.py`.
